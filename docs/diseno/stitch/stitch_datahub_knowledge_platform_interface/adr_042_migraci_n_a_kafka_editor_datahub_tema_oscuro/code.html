Sugerencias del sistema

Este documento formaliza la transición del orquestador central de cobros desde un esquema REST sincrónico hacia una topología reactiva distribuida. La migración busca garantizar un desacoplamiento estricto entre el motor de autorización transaccional, el módulo de prevención de fraudes y el microservicio de liquidación checkout-service-v2. Consultar además la especificación en la Documentación interna de Apache Kafka en Santander Tech.

# 1. Contexto y Problemática

El crecimiento proyectado del 400% en el volumen transaccional de pagos móviles evidenció fallos estructurales en la topología HTTP síncrona:

  1. 01
    Efecto cascada por latencia acumulada: Bloqueos en llamadas a pasarelas adquirentes externas agotaban el pool de hilos de los servicios upstream en menos de 12 segundos.
  2. 02
    Pérdida de eventos durante caídas temporales: Falta de un ledger inmutable con capacidad de bufferizado y repetición secuencial (*event replay*).
  3. 03
    Rigidez en auditoría PCI-DSS: Dificultad para garantizar trazabilidad forense idéntica entre entornos sin duplicar lógica de persistencia.

«La latencia P99 en días de alta demanda (Black Friday) superó los 1800ms con un error rate sostenido del 2.3% en la confirmación de cargos de débito y crédito.»

# 2. Arquitectura Propuesta y Tópicos Kafka

Se implementará el patrón *Transactional Outbox* asistido por Debezium CDC hacia un clúster Apache Kafka multi-AZ (con retención tiering en Amazon S3):

Rust / rdkafka Config (Producer Idempotent) 
use rdkafka::config::ClientConfig;
use rdkafka::producer::{FutureProducer, FutureRecord};

#[derive(Debug, Clone)]
pub struct PaymentEventProducer {
    producer: FutureProducer,
}

impl PaymentEventProducer {
    pub fn new(brokers: &str) -> Self {
        let producer: FutureProducer = ClientConfig::new()
            .set("bootstrap.servers", brokers)
            .set("acks", "all") // Tolerancia a fallos estricta
            .set("enable.idempotence", "true")
            .set("compression.type", "zstd")
            .set("max.in.flight.requests.per.connection", "1")
            .create()
            .expect("Error al inicializar productor Kafka de pagos");

        Self { producer }
    }
}
